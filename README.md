### Featured Projects

**[Enterprise IT Support RAG Assistant](https://github.com/intarchs111/enterprise-it-support-rag)**

[![enterprise-it-support-rag](https://img.shields.io/badge/GitHub-enterprise--it--support--rag-purple?style=flat&logo=github)](https://github.com/intarchs111/enterprise-it-support-rag)

**Business Challenge** 

IT support teams repeatedly handle questions about VPN connectivity, MFA, software policies, and internal application access, even when the answers already exist across internal knowledge documentation. It creates significant support volume and increasing service desk workload.

**Solution**

Designed and built an **AI powered IT knowledge assistant** that transforms internal documentation into a searchable, conversational support experience. The system delivers grounded answers with source traceability and abstains when available knowledge is insufficient, prioritizing reliability over unsupported responses.

**Measured Results**

Evaluated against a **30-question benchmark** covering supported, paraphrased, overlapping, and unsupported scenarios, achieving **100% Top-1 source accuracy**, **100% Top-3 source recall**, and **95.2% supported-question acceptance**.

**Business Impact**

Gives employees immediate access to answers for common IT issues such as VPN, MFA, software access, and internal applications. This reduces repetitive IT support workload through employee self-service channel, reduces dependency on the service desk for repetitive questions, and allows IT teams to focus on higher value support work.

**Technology Stack:** Python, SentenceTransformers, PostgreSQL/pgvector, Ollama-Llama 3.2, Streamlit, Docker

**[Responsible Decision Intelligence (RDI)](https://github.com/intarchs111/rdi-data-ingestion) -  Governance First Decision Advisory Platform**

[![rdi](https://img.shields.io/badge/GitHub-rdi--data--ingestion-purple?style=flat&logo=github)](https://github.com/intarchs111/rdi-data-ingestion)

**Business Challenge**  
Enterprise procurement workflows need automation and intelligent guidance, but allowing AI to directly influence policy decisions introduces risks around **accuracy, accountability, explainability, and auditability**.

**Solution**  
Designed a three layered governance first decision intelligence platform that separates **document understanding, deterministic policy evaluation, and AI ready advisory intelligence**. Business rules remain the decision authority, while the advisory layer operates within controlled boundaries to explain outcomes and support human decision-making.

**Business Impact**  
- Establishes a practical approach for adopting AI **without compromising deterministic business controls**.
- Converts technical validation failures into **clear, actionable business guidance**, improving exception handling and review.
- Strengthens **decision accountability and traceability** through governed processing, audit records, and historical replay.
- Provides an extensible foundation for **human-in-the-loop workflows and controlled enterprise AI adoption**.

**Core Design:** Responsible AI · Decision Governance · Enterprise Automation · Human-in-the-Loop Architecture · Auditability

**[AI Gateway](https://github.com/intarchs111/ai-gateway) - Enterprise LLM Integration Architecture**

[![ai-gateway](https://img.shields.io/badge/GitHub-ai--gateway-purple?style=flat&logo=github)](https://github.com/intarchs111/ai-gateway)

A **centralized AI Gateway** for integrating **Large Language Models (LLMs)** into enterprise applications that decouples applications from direct LLM provider access. 

The solution establishes a clear platform boundary between applications and LLM providers, separating prompt orchestration, model routing, provider access, configuration, observability, and error handling. 

**Core Design:** AI Gateway · LLM Integration · Enterprise Architecture · Python · OpenAI Responses API

**Key Architecture highlights**

- Centralized gateway for application to LLM interactions
- Explicit separation of prompt, routing, provider, and observability concerns
- Provider agnostic error handling and controlled failure paths
- Configuration driven model selection with usage and invocation observability
- Runnable implementation with success and failure path examples
